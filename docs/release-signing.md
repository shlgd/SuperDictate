# Постоянная подпись обновлений

Это подготовленный локально механизм для следующих релизов. Уже опубликованные
ad-hoc-архивы он не переподписывает и существующие записи TCC не изменяет.

## Что сохраняется

Все публичные сборки подписываются одним самоподписанным сертификатом и сохраняют
bundle ID `com.local.superdictate`. В `release-signing.sha1` хранится только
публичный отпечаток сертификата, используемый codesign для проверки издателя.
SHA-256 архива по-прежнему проверяется независимо от подписи.

Подпись не является Developer ID и не отменяет проверку первого запуска
Gatekeeper. Пользователь самостоятельно выдаёт разрешения macOS. При переходе
со старых ad-hoc-сборок или другой подписи может потребоваться разовая повторная
выдача. Сохранение конкретных разрешений необходимо проверить на целевых macOS;
совпадение требований подписи само по себе не является таким UI-тестом.

## Ключ издателя

Хранилище по умолчанию:
`~/Library/Application Support/SuperDictateSigning/`.
Каталог доступен только владельцу; файлы имеют права 0600. В нём находятся
зашифрованный PKCS#12, его пароль и публичный сертификат. Пароль лежит рядом для
автоматической сборки: защита зависит от доступа к учётной записи и диску.
Сделайте защищённую резервную копию всего каталога. Не отправляйте его пользователям,
не добавляйте в Git и не прикладывайте к релизу. Потеря ключа потребует миграции подписи.

`bash scripts/release-signing.sh init` используется только один раз, когда ещё нет
идентичности. Команда требует OpenSSL 3 на машине издателя, не на компьютерах
пользователей. Она отказывается заменять существующее хранилище. Первичное создание
или осознанная ротация требуют сверки публичного отпечатка `release-signing.sha1`.
Не создавайте новый сертификат для каждой версии или на каждом CI-запуске.

При подписании приватный ключ временно импортируется в отдельную Keychain,
доступ к нему получает codesign. После операции Keychain удаляется, прежний список
поиска Keychain восстанавливается. Системные корни доверия и TCC не редактируются.
Операции подписания сериализуются файлом-каталогом `.signing-lock`; после аварийного
завершения сначала убедитесь, что codesign не работает, и только затем удаляйте
этот пустой каталог. Обычная ошибка освобождает блокировку автоматически.

## Сборка релиза

```bash
bash scripts/test-release-signing.sh
bash scripts/package-release.sh
bash scripts/test-signed-installer.sh
```

Результат: `dist/SuperDictate.zip`. Упаковка обязательным образом проверяет
постоянный сертификат и не откатывается к ad-hoc при ошибке. Команда ничего не
публикует. Перед выпуском отдельно обновляются версия, `update.json`, SHA-256 и
исходный коммит в установщике; затем проверяется установка именно этого архива.
Обычный `build-app.sh` без release-флага по-прежнему предназначен для разработки,
а не для подготовки публичного архива. PR-сборкам не выдаются секреты издателя.

Локальная установка на Mac разработчика остаётся через `scripts/install-local.sh`
с прежним Apple Development сертификатом. Не устанавливайте поверх неё публичный
архив ради теста: это другая идентичность. Обновлятор теперь остановит такую замену.

## Проверка обновления

Кнопка обновления проверяет подпись кандидата по designated requirement установленной
версии. Повторная проверка выполняется помощником непосредственно перед заменой.
Установочная команда также проверяет совместимость прежде, чем останавливать службу.
Другая подпись не устанавливается незаметно; текущая версия сохраняется. Исключение
для исходной ad-hoc-версии позволяет однократный переход к постоянной подписи.
Ручной сброс разрешений остаётся только отдельным подтверждённым действием настроек.

Автотесты создают, подписывают и проверяют временные `.app`-фикстуры, но никогда
их не запускают и не регистрируют. Проверяются обновление с тем же сертификатом,
смена сертификата, downgrade до ad-hoc, повреждение файлов и первичная миграция.
Они не заменяют ручную проверку: разрешить микрофон/Accessibility/Input Monitoring
сборке A, установить B, перезапустить и проверить запись, хоткей и вставку текста.
Этот последний тест на компьютере друга пока не выполнен.
`test-signed-installer.sh` отдельно проходит настоящий `install.sh` с готовым
архивом в изолированном каталоге: установка, обновление и отказ от ad-hoc-кандидата.
Запуск приложения, остановка рабочей службы и загрузка модели в этом тесте отключены.
